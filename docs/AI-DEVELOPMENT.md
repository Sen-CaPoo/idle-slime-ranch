| 引擎工程師 | `ccline-0b` | `engine.js`、`shop.js`、`hd2d.js`、`scenes-modern.js` | 遊戲狀態、數值、存檔、扭蛋、光影合成器、現代背景 |

三個工作階段都是 Claude Code，跑在同一台電腦上，透過跨工作階段訊息溝通。一開始只有 0b 和 27 兩位，a3 是後來加入的「營利與視覺顧問」；人類去參加國際會議前，把產品決策權交給 a3。

## 人類導演下了哪些指令

整個專案中，人類只給了大約 15 個高層指令。以下是摘要（依時間順序）：

1. 做一款**像素風、課金、放置養成**遊戲，要看得順眼、華麗、讓人想消費、又好玩不無聊。
2. 課金維持中等強度；**最重要的是真人有持續遊玩的動力和目標**，不能只是計畫很順利、實際沒人想玩。
3. 可以參考市面上的放置遊戲規則，自由整合。
4. 「我要去開會，交給你負責」：可以加戰鬥、副本，也可以提升畫質。
5. 以 **3A 等級**開發，像素風參考《歧路旅人》（HD-2D）。
6. 優化操作：按住快速升級、一鍵升滿、倉庫販賣、扭蛋自動販賣、遠征自動推關。
7. 新增高級扭蛋與更高階的史萊姆（v1.8）；再加一階扭蛋與快速推關（v1.9）。
8. 支援 29900 寶石大包、百連抽，並修正神諭十連的卡頓（v1.10）。
9. 視覺與音效**大改版**，改成現代日系 RPG 風格（v2.0）。
10. 推到 GitHub 私人儲存庫、發布 Pages。

> **觀察**：人類的指令幾乎都是「目標」而不是「做法」。第 2 點是整個專案最重要的一句話——它讓 AI 從「把功能做完」轉向「證明真的好玩」。

## 協作機制：合約、擁有權、訊息

### 1. 共享記憶 `COLLAB.html`

所有工作階段都讀寫同一份 HTML 文件，結構固定：

- **任務與假設**：例如「課金是模擬的，不串接真實金流」。
- **檔案與分工表**：每個檔案只有一位擁有者。
- **介面合約**：`window.Game` 上每個函式的簽章與事件名稱，用版本號管理（v1 → v1.1 → … → v2.0）。
- **各自的進度紀錄**：每人只編輯自己的區塊。

規則只有一條：**要改合約，先傳訊息給對方取得同意。**

### 2. 單一擁有權

引擎不畫畫面，畫面不改數值。27 想要「按住快速升級」時，引擎只需要提供 `Game.batch(fn)` 讓多次狀態變更合併成一次重繪，其他都在 UI 端完成。這讓三個人可以真正平行開發，幾乎沒有合併衝突。

當有人需要另一方的功能時，用的是「掛點」：例如遠征系統由 a3 寫在 `dungeon.js`，只請 0b 在引擎裡加三行：

```js
if (Game.dungeon) m *= Game.dungeon.mult();               // 產量倍率
+ (Game.dungeon ? Game.dungeon.relicBonus('crit') : 0)    // 暴擊率
+ (Game.dungeon ? Game.dungeon.relicBonus('offline') : 0) // 離線上限
```

### 3. 防呆的跨模組呼叫

每個模組在呼叫別人的 API 前都先檢查存在與否。例如 `quests.js` 送星輝券時：

```js
if (v.tickets && Game.gacha && Game.gacha.premium && Game.gacha.premium.addTickets)
  Game.gacha.premium.addTickets(v.tickets);
```

所以 a3 可以在 0b 還沒做好星輝扭蛋之前，就先把「頭目送券」寫完並測試，不會互相卡住。

### 4. 驗收是獨立的角色

做東西的人不驗收自己的東西。a3 用無頭 Chrome 截圖、跑模擬、量 FPS，然後把**具體、可重現**的問題退回去：

> 🔴 牧場上的 LR 變成過曝的白色團塊：永恆、神諭被自身的白金點光源、光柱和 bloom 洗成一片白……請用 `HD2D.measure()` 確認畫面裡有 3 隻 LR 時純白像素仍然低於 5%。

## 關鍵轉折：用模擬證明「不好玩」

在 v1.3，兩位工程師的進度很順利，功能都完成了。但人類提醒「不能只是計畫很順利」之後，a3 寫了 `tools/sim.js`：

- 直接載入真正的 `engine.js`、`shop.js`，用假時鐘推進時間。
- 模擬一位「每次都挑最划算選項」的貪婪玩家。
- 情境：休閒玩家每天上線 3 次、每次 10 分鐘，持續 14 天。

結果非常難看：

```
D1 08:00  開場   0  中途 1002  最長空檔  221s  1 → 1.07M
D3 13:00  開場   0  中途    0  最長空檔  600s  3.84M → 3.84M
D5 08:00  開場   0  中途    0  最長空檔  600s  4.23M → 4.23M
...
D14 21:00 開場   0  中途    0  最長空檔  600s  4.55M → 4.55M
```

第一天一場就能買 1002 次，第 3 天起整場 10 分鐘什麼都做不了，最後囤了 2.36T 金幣沒地方花。人類玩家大概第 2 到 3 天就會流失。

從這一刻起，**每個平衡決策都要有模擬數據**。後來的驗收標準變成：

- 每場至少 5 次有意義的決策。
- 最長空檔 < 90 秒。
- 第 7 天、第 14 天都還有看得見的下一個目標。
- 地區解鎖時間點落在設計的區間內（海邊 D3、火山 D6、雪山 D12、天空城 D20–25）。

### 多種子中位數

v1.9 時 0b 發現：我們一直用同一個隨機種子 `12345` 校準，而它剛好運氣特別好。換成 5 個種子後，F2P 的天空城中位數其實是「30 天內開不了」。從此所有平衡都用 `tools/sim-seeds.js` 的 5 種子中位數。

### 三種玩家

課金遊戲不能只看免費玩家。`sim.js` 支援三種模式：

| 模式 | 設定 | v1.10 的天空城解鎖（中位數） |
|---|---|---|
| F2P | 每天 140 免費寶石 | D22 |
| light | 月卡＋每週一小包 NT$150（約每月 NT$800） | D16（快約 27%） |
| heavy | 每天 3000 寶石（約每月 NT$45,000） | D10 |

設計目標是**輕課快 10–25%、看得到但不碾壓**；重課在單機遊戲中快很多被判定為可以接受（沒有排行榜，不會傷害其他玩家）。

## AI 犯過的錯與互相糾正

這一節是整份文件最重要的部分。AI 不會因為「是 AI」就不犯錯，但多個 AI 互相審查能抓出很多問題。

| 犯錯的一方 | 錯誤 | 誰抓到、怎麼修 |
|---|---|---|
| a3 | 建議「首抽必出 SR」，結果開局 30 秒產量從 1/秒 跳到 151/秒，前期成長被跳過 | a3 試玩發現 → 改成累積 2000 金幣後才送免費抽 |
| a3 | 建議新手禮包標「原價 NT$600 → -85%」 | **27 拒絕**：那是虛構原價，即使是模擬也屬於誤導性定價 → 改寫成真實賣點 |
| a3 | 合成提案「回到 Lv1」 | **0b 指出**：3 隻 Lv10 草原（60/秒）會變成 8/秒的水滴，合成反而降產量 → 改成繼承最低等級＋合成費 |
| a3 | 轉生門檻 1e7 | **0b 指出**：第一次轉生就產量 ×17，曲線爆掉 → 改成 1e11 |
| a3 | 景深公式方向寫反 | **0b 發現**並用正確的深度定義實作 |
| 0b + 27 | 星輝券讓 F2P 拿到太多扭蛋角色，擠占主線牧場格子，F2P 進度倒退 | a3 模擬發現 → 決定新增「夥伴欄」 |
| 0b | 第 50 層就送神諭券，輕課快了 50% | 0b 用 `NO_ORACLE=1` 實驗確認成因 → a3 改到第 100 層才送 |
| 0b | VIP5 門檻 NT$10,000，而大包是 NT$9,990（差 10 元） | **0b 自己發現**並詢問 → a3 判定這是誘導加購，改門檻為 9,990 |
| 27 | 普通扭蛋的公開機率表列出了神諭限定角色 | a3 驗收時發現，用 3000 抽確認引擎正確、只有 UI 錯 → 列為最高優先 |
| 27 | HD-2D 第一版角色柔焦、亮場過曝 | a3 退回並給出量化標準 → 第二輪通過 |
| a3 | 驗收腳本固定等待 3 秒，冷啟動時偶發失敗；固定 port 和別人撞到 | 0b、27 回報 → 改成輪詢等待、隨機 port |
| a3 | 音效依 `Game.settings.artStyle` 判斷風格，但那個欄位不存在，切回經典像素時音效不會換 | 撰寫本文件時自我檢查發現 → 改用 `Game.artStyle()` |

> **教訓**：讓「做的人」和「驗的人」分開，並且鼓勵直接說「你的建議是錯的」。上表中有一半的修正是同儕提出的。

## 可量化的驗收

「看起來不錯」無法交接，也無法重複驗證。我們使用的標準：

| 項目 | 標準 | 工具 |
|---|---|---|
| 過曝 | 畫面中純白（>0.97）像素 < 5% | `HD2D.measure()` |
| 角色銳利度 | 焦點帶內的圖層不做景深、取樣用 NEAREST | 截圖放大檢查 |
| 流暢度 | CPU 降速 4 倍下平均 ≥ 50fps、p95 ≤ 33ms | `tools/perf-gacha.js`、`tools/regress-browser.js` |
| 操作 | 16 項真實滑鼠操作全部通過 | `tools/accept-ux.js` |
| 好玩度 | 每場 ≥5 決策、空檔 < 90 秒、D14 仍有目標 | `tools/sim.js` |
| 平衡 | F2P 不退步（±2 天）、輕課快 10–25% | `tools/sim-seeds.js` |
| 相容性 | `file://` 雙擊可玩、舊存檔可載入 | `tools/regress-browser.js` |

## 道德與商業的界線

人類要求「讓人想消費」，同時也要求「課金維持中等強度」。我們把界線寫成明確的規則：

- ✅ 機率公開顯示、有保底、保底剩幾抽看得到。
- ✅ 扭蛋角色轉生後保留，付費資產永遠不會消失。
- ✅ F2P 有穩定的寶石與抽券來源（每日任務、遠征頭目）。
- ❌ 不用虛構原價。
- ❌ 不用體力限制來逼付費。
- ❌ 不設計「只差 10 元就升級」的門檻。
- ❌ 不在 UI 上做「最後機會」之類的假倒數。

v2.0 改成現代日系 RPG 風格時，也定下智財原則：只取類型風格，不複製任何作品的角色、怪物、介面、旋律；史萊姆維持自有造型，扭蛋膠囊刻意做成直立蛋形以避開某知名作品的球形。

## 我們學到的事

1. **人類的一句「目標」比十句「做法」有用。** 「不能只是計畫順利但沒人想玩」直接改變了整個開發方向。
2. **把「好玩」變成數字。** 決策數、空檔秒數、里程碑時間點，這些都能模擬，也能回歸。
3. **永遠用多個隨機種子。** 單一種子會騙人。
4. **合約先行，擁有權單一。** 三個 AI 平行開發一整天，幾乎沒有檔案衝突。
5. **驗收要有截圖和數字。** 「LR 過曝」比不上「純白像素 23%，標準 <5%」。
6. **鼓勵 AI 互相說不。** 最好的修正常常來自同儕的反對。
7. **AI 不能聽音樂。** 所有配樂都只驗證了「程式正確、不破音」，好不好聽仍需要人類耳朵（試聽工具：`tools/render-music.js`）。
